# Resilience Modules — May 2026 Build

CC0. Python 3, stdlib only. Falsifiable.

Six modules documenting constraint-removal geometry as resilience
architecture. Built during overnight conversation while truck parked
at Exit 88 TA, I-94 Wisconsin, waiting out the May 18 tornado-watch
stormline.

Each module stands alone. They reference the same underlying pattern:
external constraints imposed on distributed/adaptive systems convert
distributed resilience into monocultural vulnerability. Removing the
external constraint releases adaptive capacity that already exists in
the substrate.

## Modules

### `constraint_removal_solutions.py`

When constraint REMOVAL solves problems better than constraint ADDITION.
Case studies: Bolivia, Kenya, Argentina 2001, Greece 2010s.
Implementation paths ordered by speed (non-enforcement, municipal
authorization, emergency declaration, legislative change).

### `distributed_node_economy.py`

Economies where fragmentation is structural feature, not vulnerability.
Bolivia worked example: Altiplano, Yungas, Amazon, Valles as
semi-autonomous nodes with inter-node trade. Cascade resistance metrics.

### `trust_network_activation.py`

Social-technology mechanisms from religious movement and informal
economy research. Network density, demonstration, communal ritual,
crisis responsiveness, costly signaling, local adaptation,
decentralized authority. Documented scaling rates (Argentina trueque,
Greek alternative currencies, early Christianity, Pentecostalism,
Mormon expansion, Korean Christianity).

### `place_identity_restoration.py`

Psychological/cultural mechanism by which identity shifts between
place-based (stewardship) and money-based (extraction). Generational
progression. Restoration requirements. Neuroplasticity windows.
Language pattern measurement framework.

### `dual_layer_economic_system.py`

Parallel currency + barter as transition architecture. Currency layer
satisfies external compliance (IMF, debt servicing, identity-protection).
Barter layer enables local survival. No confrontation required; just
remove regulatory constraint on parallel layer. Crisis response timeline:
day 0-7 non-enforcement, week 1-4 municipal activation, month 1-3
emergency formalization, month 3-year 1 permanent integration.

### `language_substrate_preservation.py`

AI training data degradation correlation. Documents how training data
composition (post-2000 dominant, under-30 demographic over-represented)
correlates with cognitive metric declines in the same population.
Feedback loop stages. Detection simulations AI systems can run on
themselves. Corrective training principles.

## Common Architecture

Every module follows the same structure:

1. Data classes for core concepts
1. Documented examples or case studies with citations
1. Measurement or assessment functions
1. Falsifiable predictions with explicit refutation conditions
1. Main block printing summary statistics

No external dependencies. No frameworks. No build steps. Just Python.

## Usage

Each module runs standalone:

```bash
python3 constraint_removal_solutions.py
python3 distributed_node_economy.py
python3 trust_network_activation.py
python3 place_identity_restoration.py
python3 dual_layer_economic_system.py
python3 language_substrate_preservation.py
```

Each prints a summary of what it documents.

## Falsifiability

Every module contains explicit FALSIFIABLE_PREDICTIONS with:

- specific testable claim
- method for testing
- evidence required
- conditions under which the prediction would be falsified

These are designed to be runnable against real-world data when it
becomes available.
